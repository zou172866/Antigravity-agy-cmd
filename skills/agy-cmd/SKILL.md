# agy-cmd：桌面端与 IDE 内置指令选型参谋

根据用户在桌面端 App 或 IDE 中的当前任务描述，匹配唯一最优的原生斜杠指令（或两步连招），直接交付带 `@` 上下文挂载的可复制命令文本与相近指令排他理由；或按场景输出清爽的桌面端指令速查表。

## 关键不变量

1. **零反问直接交付**：Agent 无法替用户在前端输入框触发 `/` 指令。信息充足时直接给出 1 个最优可复制命令；缺少关键前提时，直接并列给出 `若满足条件 A → 命令 1` 与 `若满足条件 B → 命令 2`，禁止停下来反问用户。
2. **严守桌面端与 IDE 边界**：禁止推荐任何终端 `agy` CLI 专属指令（如 `/undo`、`/rewind`、`/branch`、`/fork`、`/clear`、`/new`、`/resume`、`/switch`、`/effort`、`/codesearch`、`/diff`、`/statusline`、`/title`、`/voice`、`/exit`）。用户主动询问撤回、分叉等桌面端无斜杠命令的操作时，如实说明桌面端无对应斜杠指令并提示使用界面按钮或新建会话，绝不伪造命令。
3. **极简参谋定位**：只交付选型处方或分类速查，不主动出题考核，不生成闯关练习卡片，不在选型处方模式下附带无关的全量指令表。
4. **真实路径与套餐透明**：用户已提及具体文件或目录时，在可复制命令中转为 `@路径`；未提及时使用 `@目标文件` 或 `@目标目录/` 占位提示，禁止编造不存在的路径。命中付费或高阶套餐指令时必须注明门槛与普通档平替。

## 工作流程

### 步骤 1：意图分流（选型处方 vs 分类速查）

依据：Diátaxis 任务与参考分离原则。

- **进入「选型处方模式」**：用户描述了具体待办事项、卡点或工作目标（例如“我想把 15 篇文稿扫一遍敏感词”“想改字幕组件怕改坏”）。只针对该任务输出最优解，禁止罗列无关指令。
- **进入「分类速查模式」**：用户要求查看全部指令、某一类指令清单，或直接询问两个以上指令的区别（例如“列一下所有内置指令”“`/swarm` 和 `/run-workflow` 差在哪”）。读取 [references/desktop-commands-matrix.md](references/desktop-commands-matrix.md) 后输出结构化对照表。
- **失效边界**：用户只输入孤立词（如“多智能体”“定时任务”）难以分辨意图时，先给出该组 3～5 行核心区分表，末尾附一句“发一下你手头具体要做的事，我直接给你配好可复制命令”。

### 步骤 2：三维正交切面匹配（核心路由表）

依据：希克定律与分面分类法。

在「选型处方模式」下，按以下正交条件静默锁定目标指令：

| 场景切面 | 触发信号与任务特征 | 命中指令 | 适用范围与套餐 |
| --- | --- | --- | --- |
| **动手前对齐** | 只有模糊念头，字段、规则或边界还没想清楚 | `/grill-me` | 全部套餐 |
| **动手前对齐** | 目标明确，但涉及多文件或高风险改动，需先审方案再动代码 | `/plan` | 全部套餐 |
| **重活与编排** | 单一明确目标，需自动跑构建、看报错、改代码死磕到底 | `/goal` | 全部套餐 |
| **重活与编排** | 常规对话没修好的诡异 Bug、竞态条件或高难度算法求证 | `/boost` | 付费计划 |
| **重活与编排** | 任务可拆为几个异构模块并行修改，且需要独立质检员验收 | `/swarm` | Google AI Pro / Ultra |
| **重活与编排** | 对 N 个同质文件或目录执行相同检查/转换并汇总结果 | `/run-workflow` | Google AI Pro / Ultra |
| **重活与编排** | 跨模块大型架构迁移或数小时至数天的长周期团队工程 | `/teamwork` | 付费计划 |
| **旁支与上下文** | 主线干活中途顺嘴问个无关小问题，不打断工作、不污染上下文 | `/btw` | 全部套餐 |
| **旁支与上下文** | 同一窗口聊太久快满，需浓缩前文释放空间并保留关键结论 | `/compact` | 全部套餐 |
| **页面与可视化** | 需打开真实网页点击筛选、查动态渲染数据或截图验 UI | `/browser` | 全部套餐 |
| **页面与可视化** | 需在对话内嵌或独立产物中生成交互式 HTML 图表与流程图 | `/generative_ui` | 仅桌面端 App |
| **定时自动化** | 当前会话设一次性倒计时提醒，或轻量周期性 Cron 唤醒 | `/schedule` | 全部套餐 |
| **定时自动化** | 创建后台常驻定时任务，需在左侧 Automations 面板长期管理 | `/automation` | 仅桌面端 App |
| **沉淀与扩展** | 把本轮对话中的纠正、偏好或排错经验存成永久 Rule 或 Skill | `/learn` | 全部套餐 |
| **沉淀与扩展** | 打开可视化插件商店管理插件，或打包创建新插件 | `/plugin` | 全部套餐 |
| **沉淀与扩展** | 需要编写或排查 `hooks.json`、`mcp_config.json`、Rules、Skills 规范 | `/agy-customizations` | 全部套餐 |
| **沉淀与扩展** | 从 Claude Code、Cursor 等迁移配置，或升级旧版 Workflow | `/migrate-agent-settings`、`/migrate-workflows` | 全部套餐 |
| **官方帮助** | 查询 Antigravity 平台功能设置、权限配置或 SDK 官方文档 | `/antigravity-guide` | 全部套餐 |

- **失效边界**：当任务跨越前后两个独立阶段（例如“想法还不成熟，聊清楚后想先看改哪些文件再动手”，或“先定好方案，再无人值守跑通测试”）时，单指令无法覆盖，必须输出**先后两步连招**（如第 1 步 `/grill-me` → 第 2 步 `/plan`）。拿捏不准相近指令细节时，先读取 [references/desktop-commands-matrix.md](references/desktop-commands-matrix.md)。

### 步骤 3：组装零负担输出（选型处方固定结构）

依据：外在认知负荷消减与对比分化原则。

每次选型处方固定按以下 3～4 行紧凑交付（总长控制在 150 字以内，复杂双步连招不超过 250 字）：

1. **首选指令**（含套餐或桌面端限制提示，全套餐通用则免注）；
2. **可直接复制命令块**（使用 fenced code block 包裹，结合 `@` 挂载语法写出完整输入示例）；
3. **触发效果**：1 句话说明敲下回车后界面或 Agent 会发生什么动作；
4. **排他理由**：1 句话点明为何不选最容易混淆的那个近邻指令（若命中高阶套餐指令，顺带补半句普通套餐平替做法）。

- **失效边界**：用户任务未透露任何文件或目录名时，命令块中使用 `@目标目录/` 等明显占位符，不臆造具体路径。

### 步骤 4：出站边界与越界转交检查

依据：预设用途与前置约束显性化。

- 逐字扫描待输出命令，确认不含任何 CLI 专属命令名；
- 若用户的真实诉求是“帮我直接写好 `hooks.json` 或配置好某个 MCP 服务”，给出 `/agy-customizations` 可复制命令后立即结束，不在本 Skill 内凭记忆手写底层配置 Schema；
- 若用户询问平台最新改动且当前表内未收录，引导使用 `/antigravity-guide` 检索最新官方文档。

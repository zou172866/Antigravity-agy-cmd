# agy-cmd v2.3 普通用户执行提案

**建议先交付两个可以分别验收的改动。** 第一项让免费用户在已批准的实施计划里，少遇到“代码改完、测试没跑、AI 却说完成”。第二项让需要独立意见的用户打开一次复核。主 Agent 负责实施和运行验证，一个只读子智能体负责挑错。这样，一份普通计划默认新增零个子智能体，开启复核后只新增一个。

这份提案记录 v2.3 的设计取舍。审阅基线是 v2.2.0（`7fa48bcdba`）及当时工作树中的审批去重和后台唤醒修复。仓库已采用静态 `cmd-verifier`，其声明的唯一工具是 `read_file`。下文的验收情境是目标，免费 App 与 IDE 的实际派工和权限仍需分别验证。[当前使用说明](../../README.zh-CN.md) · [角色定义](../../agents/cmd-verifier.md)

## v2.2.0 审阅时的观察

| 审阅时的复核结果 | 对实现的影响 |
| --- | --- |
| 父会话的 `PostToolUse.matcher` 不匹配 `invoke_subagent`，子会话又会被入口过滤。直接给现有分类函数输入派工事件，结果为 `[]`。 | 在子会话执行的编辑和测试无法作为父级 Stop 的依据。仅添加派工 matcher 也只能证明发起了调用。[Hook 配置](../../hooks.json) · [事件入口](../../hooks/post-tool-use.mjs) |
| 主线程成功编辑源码后直接结束，现有 Stop 返回 `all_green_or_no_failure`。缺少工具回执的 `npm test` 得到 `isVerify: true, failed: false`。`echo test` 也能命中验证关键词，同时带有只读命令标记。 | “没有观测到失败”“命令像测试”“测试已通过”必须分开。新功能不能用 `latestPassTs` 或 `isVerify && !failed` 判通过。[分类与 Stop 实现](../../hooks/lib/detector.mjs) |
| 审阅时，另一插件 `agy-dart` 的 `agents/dart-reviewer.md` 描述为只读审查，实际工具表含 `run_command` 和角色自己的 MCP `run_checks`。关闭 `inheritMcp` 只影响继承。 | 计划复核若承诺只读，角色可用工具里就应只有读文件和搜索。主线程运行项目命令。[官方角色配置](https://antigravity.google/docs/build-plugins/) |
| 批处理规则遇到 ≥5 个语义对象会先输出 `/run-workflow` 徽标，之后才判断是否降级。 | 即使不新增任何角色，修正路由顺序也能立即改善免费体验。常驻规则、技能说明和 Python 安装器内嵌规则应一起改。[路由规则](../../rules/AGENTS.md) · [技能说明](../../skills/agy-cmd/SKILL.md) · [安装器](../../skills/agy-cmd/scripts/setup_auto_router.py) |

## 七项裁决

| 简报争议 | 决定与理由 |
| --- | --- |
| 1 · 子智能体事件盲区 | **首版让父会话成为唯一写手和最终验证者。** 不合并父子事件流，不解析子智能体的“已完成”文本，不把派工当成发生过编辑。将来试验独立 Coder 时，要等写手真正结束、改动出现在父工作区，再由父级验证最终版本。 |
| 2 · 规则继承 | **保留项目规则，限制工具。** 自定义复核角色优先 `inheritCustomizations: true`、`inheritMcp: false`，并验证实际有效工具。交接提供目标路径及适用的根目录和嵌套 `AGENTS.md` / `GEMINI.md` 路径，审阅者按需读原文。以后若引入写手也默认继承规则。缺少本机测量时，不为推测的 token 节省牺牲项目约束。[官方插件规范](https://antigravity.google/docs/build-plugins/) · [官方目录规则](https://antigravity.google/docs/rules/) |
| 3 · 何时值得调用 | **默认单线程，独立复核由用户开启。** “3 个文件、50 行”足以按既有规则申请 Plan，不能据此推断多开一个模型有收益。值得用户选用的例子是公共接口行为改变、跨模块约定容易漏查，或验收失败代价高。首版不建复杂度打分器。 |
| 4 · Stop 误拦截 | **只在有明确验收方法的已批准实施中补救一次。** 等宿主自然结束并确认本次相关源码确实写入后才考虑补验。纯文档、仅注释、模板示例、无可用检查、证据不足或用户要求跳过时放行。用户仍应知道哪些内容没有验证。 |
| 5 · 审查粒度 | **一次独立复核查两件事。** 先逐条看计划要求及越界修改，再看最易出错的路径和测试遗漏。每个阻断问题给出文件位置、触发条件或反例。父级提交真实命令结果，复核者不用重复跑一套测试。首版不承诺任何漏检率或节省比例。 |
| 6 · 并发写入 | **从 v2.3 移除多写手选项。** 普通子智能体与 Swarm worker 的文档对工作区各有说明。在 Windows 脏工作树、未跟踪依赖和非 Git 项目上，文件归属、环境和合并都需要另行验证。单写手及只读复核只用 `inherit`。卡壳时先保留现有单路排查。有两条可独立反证的假设且单路确有瓶颈时，再试两个只读侦察者。[普通子智能体工作区](https://antigravity.google/docs/subagents/) |
| 7 · 与 agy-dart 共存 | **先实测内置 `research` 的有效工具。** 如果目标免费宿主能证明它仅可读取和搜索，就直接复用。若有通用 shell、写入途径或权限无法核实，则打包一个最小静态 `cmd-verifier`。在目标构建上确定一个入口，不在每次任务里逐个试角色。首版省去 `cmd-coder`、`cmd-scout` 和动态 `define_subagent` 的创建、去重及恢复逻辑。安装了 `agy-dart` 也使用同一入口。 |

## 第一项交付 · 免费计划的改后补验

1. **记录批准，保持普通轮次安静。** 复用现有按钮批准、计划后聊天确认及去重逻辑。免费分支只记录本次批准执行的范围，标准模式此时不注入提示。研究计划、只读 Plan Mode、等用户回答、普通“继续”、后台唤醒和旧通知重放都不能启动新的实施。下一次真正的用户任务、撤回或重置应隔离旧状态。[审批识别](../../hooks/lib/detector.mjs) · [回放处理](../../hooks/lib/transcript.mjs)
2. **确定哪些编辑需要补验。** 只考虑本次在工具证据中确认写入的相关代码。计划已指定可运行检查，或能在本次变更所属工作区识别到已有项目检查时，才有补验依据。首版可从包目录的已声明测试脚本，或本次同包已成功跑过的真实检查起步。代码后缀只作线索。无从辨别注释替换、目标包、同名文件或未知编辑工具时，保守放行。改真实运行配置且计划要求验证，应纳入。避免逐轮扫仓、解析任意计划正文或让 Hook 自己执行项目命令。
3. **只认与最终改动对应的终态。** 父级运行与目标包和验收项匹配的命令。有效证据包括宿主给出的成功退出状态、实际执行了检查项的成功结果，或对应编辑工具返回的内联验证成功。后台运行要按同一工具步骤关联真实完成事件。验证开始后又有相关写入，旧结果失效。同一步批量编辑附带的内联验证可以有效。打印文字、列目录、别的包测试通过、命令返回空、仍在运行、仅有子角色回执均不记为通过。必要时在分类阶段保留包范围和步骤信息，旧日志缺字段视为未知。
4. **把“漏跑一次”和“跑过且失败”分开。** 在现有用户取消、宿主上限、后台未空闲、等审批或提问、原生 `/goal`、重试关闭和重试范围等退出条件之后判断。适用检查漏跑，才由 Stop 返回一次 `continue`，告诉主 Agent 运行哪项检查。没有环境则说明具体原因。一次额度绑定本次批准的实施，跨后台唤醒不重置，包括无限重试模式。补验占用用户允许的总续跑次数，单独标原因，不增加面板的“失败重试”统计或 Star 里程碑。已有明确失败进入原失败重试逻辑。用尽额度就如实交付当前状态。[Stop 入口](../../hooks/stop.mjs) · [设置与计数](../../hooks/lib/settings.mjs)
5. **修复免费批处理文案。** 免费或套餐未知时默认直接分批处理，不主动推荐或调度这四个重型命令。用户在支持的 App 明确要求本次使用 Swarm 或 Workflow 时沿用其选择。同步常驻规则、安装器规则副本、技能路由及受影响的面板或说明文字。付费 Boost 继续服从已有开关。沿用现有首次安装提示与非触发轮次的 Hook 输出契约，正常 `PreInvocation` / `PostToolUse` 为 `{}`，正常 Stop 为 `allow`。

## 第二项交付 · 可选的一次独立复核

- **入口。** 免费面板增加「计划实施后独立复核」开关，说明“每份已批准的实施计划最多调用一位审阅者，会额外消耗配额”。建议独立布尔字段 `freePlanReviewEnabled`，旧配置和新安装均默认关闭。只保存这个字段，不能借写 `boostEnabled` 切换套餐。同步 JS 设置、Python 设置读写、Sidecar 保存和回读，覆盖切换套餐再切回的场景。
- **交接。** 主 Agent 完成编辑及相关验证后发送一次任务书，含计划验收条目、本次改动的相对路径和关键 diff、适用规则文件、命令及已确认结果或缺测原因。交接范围排除工作区原有的无关修改。在非 Git 项目也可提供本次编辑片段。这样，审阅者无需终端即可看到改了什么。模型使用目标免费宿主已证实可用的档位，不要求用户切换到更高档。
- **回执。** 审阅者返回「通过／需修复／证据不足」，指向文件位置和具体问题。主 Agent 处理阻断项并验证修复后的版本。首版同一批准只发起一次独立复核。复核后又改了代码，交付中注明修复已由主线程验证的范围。角色不可用、超额或调用失败时回到主线程，说明独立复核未完成，绝不轮流试角色或反复唤醒。
- **安装。** 若采用静态角色，设置 `mainAgent: false`、`subagent: true`，仅授予目标宿主实测可用的读取与搜索工具。同步修改 Python 安装目录和漂移校验目录清单，审阅基线的两处清单均缺 `agents`。验证干净安装、覆盖升级、无 `agy-dart` 及两插件同装。静态方案会给宿主的角色列表多加一个条目。仅 Hook 的稳态注入量可以保证为零。[安装与漂移校验](../../skills/agy-cmd/scripts/setup_auto_router.py) · [角色注册规范](https://antigravity.google/docs/build-plugins/)

## 执行与验收

在源码仓库依次完成两项交付，先把第一项独立测绿。用一条脱敏的真实 Stop 事件核对目标版本的正常结束原因、`fullyIdle` 和后台完成格式。审阅时的代码只处理 `NO_TOOL_CALL` 一类正常结束，其他值会放行。账本只需保存本次批准的标识、最近相关编辑、验证证据和是否已提醒，避免事件日志截短后重复提醒。一个包通过不能抵消另一个包待跑或已失败的验收项。[Stop 契约](https://antigravity.google/docs/hooks) · [会话状态](../../hooks/lib/state.mjs)

第二项按免费 App 和 IDE 的实际能力分别验收。缺少某一版本的真实账号或宿主时，交付可独立工作的部分，列明该组合待测，保留标准执行路径。暂缓配额倒计时、按 transcript 大小催促压缩、自动写进度文件、双路卡壳侦察和 Hook 内本地快检。

| 验收情境 | 通过条件 |
| --- | --- |
| 纯问答、确定性查找、明确的 1～2 文件低风险修改 | 没有新增 Plan、徽标、子智能体或补验续跑。免费批处理不输出四个重型命令的调度徽标。 |
| 已批准计划，本包业务代码确实已改且已有测试，但主 Agent 直接结束 | 在用户续跑额度内只提醒一次。停在同一状态、后台唤醒、重复 Stop 均不会再提醒。真实失败遵循既有上限。 |
| 最后一次编辑前已通过、后台检查时又编辑、空回执、`echo test`、另一包通过 | 均不能使最终改动变绿。最后一次编辑后本包真实测试通过、同一步编辑附带真实内联 PASS 均可结束。 |
| 纯文档或注释、无测试入口、用户跳过、原生 `/goal`、取消、预算耗尽、等待批准 | 新功能不强制续跑。缺测时不会宣称测试通过。只读 Plan Mode 的方案可在正文等待确认，绝不自动调用 `exit_plan_mode`。 |
| 免费标准／免费开启复核／旧付费 Boost | 正常实施计划分别新增 0／最多 1 个审阅子智能体／沿用已有付费行为。同一批准重放不重复派工。就已开启复核的计划，验证嵌套目录规则可见、审阅者不能运行任意 shell 或写文件，角色不可用时仍能完成主流程。 |

提案审阅时在改动前的工作树运行 `npm.cmd test`，48 项通过。另运行 `python -B -m unittest discover -s test -p "test_*.py"`，10 项通过。这些数量仅代表改动前的基线。宿主验收还需一个免费桌面端真实样例，记录宿主及版本、开关、实际派工次数、验证命令及其终态。App 与 IDE 能力分栏记录。比较单线程与可选复核时，记下耗时、额外调用和经确认的新增发现。平台未提供的 token 或配额数字标为未观测。
